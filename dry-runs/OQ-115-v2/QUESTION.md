QUESTION (OQ-115 — Build a legal-task-aware model router):
Lawyers running multiple coding/agent harnesses route between models by gut — cheap model for mechanical work, frontier model for hard reasoning — and burn through subscription token caps with no system deciding where each request goes. Generic routers (OpenRouter-style) optimise on raw API price and ignore what actually matters for legal work: different legal task types (litigation reasoning, transactional drafting, contract review, legal research, citation-checking) have different best-fit models, and the stakes differ wildly (an internal memo vs. a filing that goes on the record). Build the router that reflects that.
